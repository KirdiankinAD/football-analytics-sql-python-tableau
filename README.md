# ⚽ Football Match Analytics

## О проекте

Аналитический проект по исследованию футбольных матчей средствами **PostgreSQL** с дальнейшим развитием анализа в **Python** и визуализацией в **Tableau**.

Проект построен вокруг реального набора данных примерно из **95 000 футбольных матчей**, охватывающего **18 лиг и кубков** и период с 2000-х до 2020-х годов.

Основная задача SQL-части — пройти полный аналитический путь:

**грязный CSV → ETL → нормализованная модель данных → аналитические запросы → проверка гипотез → интерпретация результатов.**

## Данные и подготовка

Исходный файл содержит 95 384 строки и 69 столбцов. В данных присутствуют смешанный разделитель `;`, локализованные десятичные значения и проценты в текстовом формате.

Для подготовки данных использована staging-таблица с типом `TEXT`, после чего выполнены очистка через `regex` и `UPDATE`, а затем типизированная загрузка через `INSERT ... SELECT` с приведением типов.

## Структура базы данных

В SQL-части используются 5 основных таблиц:

- `leagues` — лиги и страны;
- `teams` — команды;
- `stadiums` — стадионы и вместимость;
- `matches` — матчи, счёт, сезон, дата, посещаемость;
- `match_team_stats` — статистика команды в конкретном матче.

Таблица `match_team_stats` построена в **long-формате**: одна строка соответствует одной команде в одном матче, а `is_home` показывает её роль — хозяин или гость.

Такой подход упрощает дальнейшую агрегацию статистики и уменьшает дублирование логики `CASE WHEN` для отдельных показателей.

## Что исследуется

SQL-часть содержит аналитические задачи, связанные с:

- результативностью лиг и кубков;
- посещаемостью стадионов;
- win rate команд;
- эффективностью относительно xG;
- красными карточками;
- текущей формой команд;
- домашним преимуществом;
- корреляцией посещаемости с результатом;
- частотой встреч команд;
- динамикой результативности по сезонам;
- влиянием красных карточек на вероятность победы;

Полный набор SQL-запросов находится в [`sql/queries.sql`](sql/queries.sql).

## Ключевые результаты

- Домашнее преимущество оказалось достаточно стабильным: после фильтрации малых выборок win rate хозяев находится примерно в диапазоне **0.43–0.47**.
- Красная карточка показывает наиболее устойчивый эффект: снижение win rate наблюдается во всех исследованных турнирах.
- Связь посещаемости с победой хозяев слабая с практической точки зрения: **R² = 0.014**.
- Устойчивой «инфляции голов» со временем не обнаружено: результативность заметно колеблется от сезона к сезону, но стабильного тренда не видно.
- Среди наиболее частых пар соперников заметно доминируют итальянские команды: **7 из топ-10 пар** относятся к итальянским турнирам.

## Используемые возможности PostgreSQL

В проекте применяются:

- агрегации `AVG`, `SUM`, `COUNT`;
- `CASE WHEN`;
- `JOIN` и `self JOIN`;
- многоуровневые `CTE`;
- оконные функции `ROW_NUMBER`, `LAG`, `RANK`, `DENSE_RANK`;
- условная агрегация и pivot;
- `LEAST` / `GREATEST` для нормализации пар команд;
- статистические функции `CORR`, `REGR_SLOPE`, `REGR_R2`;
- `PERCENTILE_CONT`;
- `STDDEV_SAMP`;
- работа с датами и преобразованием строковых сезонов.

## Ограничения

Некоторые результаты требуют осторожной интерпретации:

- часть команд имеет небольшое количество матчей;
- разные турниры представлены неравномерно;
- последние матчи команд заканчиваются на разных календарных датах;
- данные о стадионах могут содержать нетипичные площадки, например Wembley;
- корреляция не означает причинность;
- SQL-часть выявляет закономерности, но не заменяет полноценную статистическую проверку значимости.

## Развитие проекта

### Python

Следующий этап — статистически более строгий анализ:

- логистическая регрессия для предсказания победы;
- проверка статистической значимости эффектов;
- тестирование трендов;
- feature importance;
- анализ серий побед и поражений;
- графовый анализ частых соперничеств.

### Tableau

Финальный слой проекта — интерактивные дашборды:

- домашнее преимущество;
- head-to-head;
- влияние красных карточек;
- динамика результативности;
- посещаемость стадионов.
